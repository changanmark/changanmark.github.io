## 10.1 后处理与 Framebuffer

[源码：ch10_01_post-process.html](https://github.com/PacktPublishing/Real-Time-3D-Graphics-with-WebGL-2/blob/master/ch10/ch10_01_post-process.html) · [PostProcess.js](https://github.com/PacktPublishing/Real-Time-3D-Graphics-with-WebGL-2/blob/master/common/js/PostProcess.js)

后处理必须分两遍。Scene pass 绑定 post.framebuffer，以正常 3D program 把场景颜色写进 RGBA texture、深度写 DEPTH_COMPONENT16 renderbuffer；Post pass 绑定默认 framebuffer，使用全屏 quad program 采样颜色纹理。

renderbuffer 适合只参与深度测试而不需 shader 采样；颜色必须是 texture 才能在第二遍读。若要基于深度的雾/景深，深度也需可采样 depth texture。

### 源码时间线

`render` 绑定 FBO 调 draw，再绑定 null，选择/设置后处理 uniform，调用 post.bind/post.draw。每次 pass 必须设与目标尺寸一致的 viewport；切 framebuffer 不会自动改 viewport。后处理通常关闭 depth test/write 与 cull，是否 blend 取决于合成目标。

PostProcess 配置 NEAREST、CLAMP_TO_EDGE，分配 canvas 大小的 RGBA/UNSIGNED_BYTE 与 DEPTH_COMPONENT16，但未 `checkFramebufferStatus`，也不在 bind/draw 内自动 validateSize。resize 后必须重分配两附件；0×0 canvas 会产生 incomplete/无效尺寸。

`uInverseTextureSize=(1/w,1/h)` 把“一像素邻居”表达为 UV offset。3×3 卷积在中心及八邻采样后乘 kernel；边缘依赖 clamp。多次模糊需 ping-pong 两个 FBO，绝不能在某纹理仍挂为当前写附件时同时采样它，反馈循环结果未定义。

源码包含 normal、灰度、反相、波浪、边缘/噪声等 fragment shader。调试顺序必须先纯复制 `texture(sampler,uv)` 确认方向/尺寸，再单效果；复杂 shader 黑屏时先显示输入 texture。

RGBA8 不够 HDR/bloom。现代流程用可渲染浮点附件（检查扩展）、提亮阈值、降采样模糊、合成、tone map 和输出编码。性能近似随分辨率×每片元采样数增长，用 timer query 测每个 pass。

### 状态验收表

Scene pass：post FBO、3D viewport、scene program、depth test/write on；Post pass：default FBO、canvas viewport、post program、depth off、unit0=post color texture、fullscreen geometry。每帧逐项显式设置，交换 pass 顺序或遗漏 bind 应能被调试断言捕获。

用 readPixels 对纯复制 pass 的四角颜色做自动回归；resize 后检查 texture/renderbuffer尺寸与 canvas 一致；故意把 post texture仍挂在 current FBO时采样，开发层应拒绝反馈循环。

## 10.2 Point Sprite 粒子

[源码：ch10_02_point-sprites.html](https://github.com/PacktPublishing/Real-Time-3D-Graphics-with-WebGL-2/blob/master/ch10/ch10_02_point-sprites.html)

每个粒子只提交一个 POINTS 顶点，attribute aParticle 打包 xyz position 与 normalized remaining life。顶点 shader 写 `gl_PointSize=uPointSize*vLifespan`；片元 shader 用自动生成的 `gl_PointCoord` 在点方形内部采 spark texture。

CPU 每帧按 elapsed 秒减少生命、积分位置和重力；触地将 y=0、vy×=-0.75；死亡则回原点并随机速度/寿命。先更新预分配 Float32Array，最后一次上传整个 buffer，优于逐粒子 buffer 调用。

源码每帧 `bufferData(...,STATIC_DRAW)` 重新指定存储。STATIC 只是 usage hint，不会禁止更新，但语义不合；可用 DYNAMIC_DRAW + bufferSubData，或 orphan `bufferData(size,DYNAMIC_DRAW)` 后 subData 避免等待 GPU 仍读旧存储。不要每帧 createBuffer。

混合使用 SRC_ALPHA/ONE，是加法发光，绘制顺序影响较小但 overdraw 仍昂贵。通常保持 depth test 使粒子被场景遮挡，`depthMask(false)` 避免粒子互相写深度；源码需要显式审计是否启用 BLEND 与 depth write 状态，而不只设置 blendFunc。

点大小受 `ALIASED_POINT_SIZE_RANGE`，且 sprite 永远面向屏幕、难旋转拉伸。实例化 quad 可传 size/rotation/frame，实现烟雾与 streak。大量粒子瓶颈常是半透明方块覆盖像素，不是一个顶点的成本；圆形纹理外部 alpha=0 的片元仍可能产生 overdraw，可 discard 但也会影响 early tests。

GPU 更新可用 transform feedback：buffer A 作为 attribute 输入、B 作为 TF 输出，下一帧交换，禁止同一存储同时读写。验收时固定随机种子，比较 CPU/TF 状态；查询点大小范围，并分别测粒子数与屏幕尺寸变化对耗时的影响。

### 一帧数据流

Clock 提供 elapsed→CPU 遍历 particles 写 Float32Array→一次 buffer 上传→use particle program/上传 P/MV/pointSize→bind aParticle buffer→bind sprite texture/sampler→drawArrays(POINTS,N)。VAO 可缓存 attribute 描述，动态更新不需重建 pointer。

错误因果：remainingLife 未 clamp 可能产生负 pointSize；纹理未就绪出现黑/不完整；只设 blendFunc 未 enable BLEND 变成方块覆盖；开 depth write 导致粒子互相切洞；elapsed 过大导致穿地。分别用固定白圆、固定粒子、关闭重力逐层验证。

## 10.3 Normal Mapping 与 TBN

[源码：ch10_03_normal-map.html](https://github.com/PacktPublishing/Real-Time-3D-Graphics-with-WebGL-2/blob/master/ch10/ch10_03_normal-map.html)

法线贴图把 RGB `[0,1]` 解码为切线空间 `normalize(rgb*2-1)`。几何法线只描述低模表面，纹理法线逐片元扰动受光方向，制造细节但不改变轮廓或真实遮挡。

### TBN 基

Tangent T 对应 UV 的 +U，bitangent B 对应 +V，N 是几何法线。TBN 把切线空间向量转到工作空间；转置/逆则把 eye-space light/eye direction 转到 tangent space。源码构造矩阵后用 light/eye 方向，必须根据 GLSL column-major 写法验证矩阵究竟是 TBN 还是 transpose(TBN)，不能只看排列。

可靠顶点处理：

```glsl
vec3 N=normalize(normalMatrix*normal);
vec3 T=normalize(normalMatrix*tangent.xyz);
T=normalize(T-N*dot(N,T));
vec3 B=cross(N,T)*tangent.w;
```

源码用 vec4(normal/tangent,1)，方向 w 应为 0；也未把 T 对 N 正交化，直接 `cross(normal,tangent)`。镜像 UV 需要 tangent.w handedness，否则某些 UV 岛绿色通道反向。

### 从三角形算 tangent

边 `e1=p1-p0,e2=p2-p0` 与 UV 差构成 2×2 方程。det=`duv1.x*duv2.y-duv1.y*duv2.x` 接近 0 时 UV 退化，不能直接除。共享顶点需按三角形累加再正交化；硬边/UV seam 必须拆顶点。仓库 utils.calculateTangents 是教学简化，生产资产优先导出 glTF TANGENT vec4 或使用 MikkTSpace 一致算法。

法线图是线性数据，不能按 sRGB 解码。凹凸反向常是 OpenGL(+Y) 与 DirectX(-Y) 约定差异，可显式翻转 green 后验证。源码 Lambert 最低 clamp 0.20 属于艺术环境底光，不是纯 Lambert。

验收：依次输出几何 N、T、B、解码法线、变换后法线和最终 N·L。用完全平坦 `(0.5,0.5,1)` normal map 时应接近无 normal map 结果；镜像 UV 测试不能出现接缝反转。

## 10.4 解析式 Ray Tracing

[源码：ch10_04_ray-tracing.html](https://github.com/PacktPublishing/Real-Time-3D-Graphics-with-WebGL-2/blob/master/ch10/ch10_04_ray-tracing.html)

此例复用 PostProcess 的全屏 quad，但不先画 3D mesh。每个片元由 gl_FragCoord 构造一条相机射线，在 fragment shader 中与运动球求交并计算 Lambert。

### 球求交推导

球心 c、半径 r，射线 `p(t)=ro+t·rd`。代入 `|p-c|²=r²`：

```text
a=dot(rd,rd)
b=2dot(ro-c,rd)
c0=dot(ro-c,ro-c)-r²
D=b²-4ac0
t=(-b±sqrt(D))/(2a)
```

D<0 无交；取最小正根，若近根在相机后而远根为正，应取远根。源码只返回 `(-b-sqrt(D))/2`，遗漏 `/a`，但当前 rd 被 normalize 使 a≈1；它也没有尝试第二根，所以相机位于球内时会误判。稳健函数应检查两根和 epsilon。

命中点 `p=ro+t·rd`，单位法线 `n=(p-c)/r`。多个对象应遍历并保留最小正 t；maxDistance 是无命中的哨兵。

### 屏幕射线审计

通用做法是 `ndc=uv*2-1`，按 aspect 和 `tan(fovy/2)` 缩放，再结合相机 right/up/forward。源码使用 `-0.5 + uv*vec2(aspect,1)`，只有特定 aspect 下接近居中，宽屏中心射线 X 会偏；这是值得修正的投影模型。

uInverseTextureSize 由 canvas 尺寸计算，fragCoord 得 0～1 UV。若 drawing buffer resize 而 uniform 未更新，aspect/射线方向错误。uTime 移动球只改变球心，不涉及 BVH。

### 从解析球到光追

平面求交 `t=dot(p0-ro,n)/dot(rd,n)`，分母近 0 为平行。阴影射线从 `p+n*epsilon` 发向光，只接受小于光距离的遮挡，避免 self-intersection acne。反射用 `reflect(rd,n)` 并有限循环；epsilon 应随场景尺度选择。

这不是 path tracer：没有三角形/BVH、随机 BRDF、多帧累积、Russian roulette 或降噪。每增加对象/反弹，成本约为像素数×求交次数。调试依次显示 ray direction、hit mask、t 深度、normal 色，最后才加光照；用 timer query 和降低分辨率判断片元瓶颈。

验收：相机外、相切、相机在球内三种情况验证两根；窗口变宽时中心射线仍指 camera forward；加入第二球后无论数组顺序都选最近正 t。
