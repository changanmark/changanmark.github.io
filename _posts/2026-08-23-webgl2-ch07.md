## 7.1 纹理坐标通道

[源码：ch07_01_textured-cube.html](https://github.com/PacktPublishing/Real-Time-3D-Graphics-with-WebGL-2/blob/master/ch07/ch07_01_textured-cube.html)

初始例仍以顶点/材质色绘制，但加载的 `cube-texture.json` 已含 textureCoords。这是有意把问题拆开：先确认 position、normal、UV 三套顶点数据能正确进入 VAO，再引入图片异步和 sampler。

UV 通常是二维无量纲坐标，(0,0) 到 (1,1) 覆盖一张图。它不是像素坐标，也不要求限制在 0～1；超界由 wrap 参数决定。光栅器会对 varying 做透视正确插值，近似形式是先插值 `uv/w` 和 `1/w`，再相除，避免倾斜面纹理游动。

`pixelStorei(UNPACK_FLIP_Y_WEBGL,true)` 是 context 级上传状态，只影响之后从 Image/Canvas 等源上传像素，不会修改模型 UV。HTML 图像行原点与很多 UV 管线不同，但是否翻转取决于资产约定；cubemap 更不能无脑继承。

验收：把 UV 作为颜色 `vec4(fract(uv),0,1)` 输出，六个面应方向可解释；检查 Scene 创建 UV buffer 时 size=2、类型 FLOAT、stride/offset 匹配。若 attribute location 为 -1，说明 shader 未使用而被优化，不应 enable。

### 一帧内发生了什么

load 解析 JSON，Scene.add 只在 program 的 aVertexTextureCoords location≥0 时创建 UV VBO并配置 VAO；当前 shader 若未消费 UV，编译器会移除输入，数据虽在 CPU 资源中却不进入 GPU attribute。draw 仍只上传矩阵/材质并提交 cube indices。

这一步的验收价值在于分层：若 UV debug 色错误，先修资产/attribute，不能用图片 flip/filter 掩盖。现代资产格式还要标注每个 primitive 使用哪套 TEXCOORD_0/1，lightmap 与 baseColor 不一定共用 UV。

## 7.2 异步加载与完整采样链

[源码：ch07_02_textured-cube-final.html](https://github.com/PacktPublishing/Real-Time-3D-Graphics-with-WebGL-2/blob/master/ch07/ch07_02_textured-cube-final.html)

顶点 shader 把 `aVertexTextureCoords` 传给片元；片元以 `vColor * texture(uSampler,uv)` 合成。JS 的时序是 createTexture、Image 请求、onload 内 bind/texImage2D/参数设置，draw 时 active unit、bind texture、sampler=unit index。

```js
gl.activeTexture(gl.TEXTURE0);
gl.bindTexture(gl.TEXTURE_2D, tex);
gl.uniform1i(uSampler, 0); // 不是 gl.TEXTURE0
```

sampler 存的是 0、1…槽号；TEXTURE0 是传给 activeTexture 的枚举。纹理对象可在不同帧绑定到不同 unit，sampler 不持有对象引用。

图片未到时纹理可能 incomplete，采样结果不可依赖。可靠加载器创建后立即上传 1×1 洋红占位，并设置非 mip min filter；onload 替换真实图，按需 generateMipmap。还需 onerror、response/CORS 诊断，以及组件销毁后的回调防护。

源码只设 NEAREST min/mag，无 mip 依赖。`vColor * texel` 会使任一通道相乘变暗；若目的是显示原图，应先只输出 texel，以此隔离 UV/加载问题，再恢复光照。

验收：网络限速时占位色可见，加载后无黑闪；故意改错 sampler 为 1，应稳定复现错槽；用 2×2 四象限测试纹理判断 flipY 和 UV 朝向。

### GPU 采样细节

光栅器插值 UV，片元 sampler 使用隐式导数估算 footprint；NEAREST 从 level0 选一个 texel。texture lookup 返回 normalized RGBA，随后与 vColor 相乘；depth/blend 再处理最终 fragColor。纹理上传和 draw 都排入 GL 命令流，Image.onload 只表示浏览器像素可用于上传，不表示 GPU draw 已同步完成。

图片加载完成后 callback 会修改全局 binding；若此时 render 正在用其他 texture unit，状态可能被污染。加载器可保存/显式设 active unit，或让 renderer 每 draw 完整重绑材质，不能依赖 callback 后残留状态。

## 7.3 过滤与 Mipmap

[源码：ch07_03_texture-filters.html](https://github.com/PacktPublishing/Real-Time-3D-Graphics-with-WebGL-2/blob/master/ch07/ch07_03_texture-filters.html)

放大过滤只有 NEAREST 与 LINEAR：前者取最近 texel，像素块明显；后者取相邻 2×2 双线性。缩小时一个屏幕像素可能覆盖很多 texel，仅在 level 0 做 LINEAR 会闪烁和浪费带宽。

Mipmap 把尺寸逐级减半到 1×1。min filter 的四个 mip 选项分别组合“层内 nearest/linear”和“层间 nearest/linear”；LINEAR_MIPMAP_LINEAR 是三线性。完整 mip 链总像素 `1+1/4+1/16...≈4/3`，即约多 33% 内存。

源码上传后 `generateMipmap`，因此可安全选择 mip min filter。MAG_FILTER 不能选择 mip 枚举，传入会触发 INVALID_ENUM。WebGL2 支持 NPOT 纹理 mip/repeat；若兼顾 WebGL1 则限制更多。

斜视表面 footprint 高度各向异性，三线性仍会糊；可查询 `EXT_texture_filter_anisotropic` 并在设备最大值内设置。不要默认拉满，带宽成本要测。

验收：让带高频棋盘的地面延伸远处，对比 NEAREST、LINEAR、三线性；用 `textureQueryLod` 不一定在所有目标阶段可用，调试也可手工以不同纯色填每个 mip level，观察被选择的层。

### GUI 状态与错误因果

texParameteri 修改当前绑定 texture object。回调前若 texture 未 bind，可能 INVALID_OPERATION 或改错对象；应由 Texture.setFilters 显式 bind。选择 `LINEAR_MIPMAP_LINEAR` 但缺任一所需 level 会使采样得到不完整纹理表现（常见黑色），并非 UV 为零。

Mipmap 生成必须在 level0 上传后执行；之后若替换 level0 内容/尺寸，旧 levels 需重新生成。动态视频纹理通常不用每帧完整 mip，需权衡闪烁与生成成本。

## 7.4 纹理寻址

[源码：ch07_04_texture-wrapping.html](https://github.com/PacktPublishing/Real-Time-3D-Graphics-with-WebGL-2/blob/master/ch07/ch07_04_texture-wrapping.html)

顶点 shader 将 UV 放大三倍再减 1，故范围超出 0～1，便于观察 `TEXTURE_WRAP_S/T`。CLAMP_TO_EDGE 把坐标夹到边缘 texel；REPEAT 取小数周期；MIRRORED_REPEAT 每个周期交替翻转。

S/T 可独立设置。例如 S repeat、T clamp 会横向平铺、纵向拉边。参数属于当前绑定 texture object，不属于 texture unit；GUI callback 调 texParameteri 前必须先绑定正确对象，否则会改到当前槽里另一张纹理。

接缝可能来自：源图本身不无缝、边缘 texel 不匹配、mip 下采样跨边界、UV 岛 padding 不够、精度或 cubemap 面方向。不能看到缝就一律改为 clamp。

验收：用带坐标文字与彩色边框的测试图，分别让 S/T 取三种模式；采样 u=-0.25、0.25、1.25、2.25，手算 repeat/mirror 结果再与画面比对。

### 执行链与采样数学

VS 先把原 UV 变成 `3uv-1`，光栅化插值后 FS 才对每片元执行 wrap/过滤；wrap 不是 CPU 修改 UV，也不会改变 VBO。REPEAT 等价于取 fract（负数的 fract 仍落入 0～1），mirror 根据整数周期奇偶翻转。

现代 Material 将 wrap/filter 作为 sampler state 描述。WebGL 的采样参数存在 texture object 上，因此同一图若两个材质需要不同 wrap，要么切参数造成状态变更，要么创建共享像素但不同 texture objects；WebGL2 sampler objects 也可把采样状态与纹理分离。

## 7.5 多纹理初始版

[源码：ch07_05_multi-texture.html](https://github.com/PacktPublishing/Real-Time-3D-Graphics-with-WebGL-2/blob/master/ch07/ch07_05_multi-texture.html)

虽然章节开始讨论 multi-texture，这个 initial 仍只有一个 `sampler2D uSampler` 和 TEXTURE0。它建立基线：第一张纹理、UV、过滤和 unit 绑定必须先正确，第二张加入后才知道故障来自哪里。

纹理数量不能只看 `MAX_COMBINED_TEXTURE_IMAGE_UNITS`；顶点/片元阶段各自还有上限，且实际性能受采样次数、分辨率、cache 命中和分支影响。一次 draw 中所有 sampler 类型与绑定目标必须兼容。

建议把 Texture 对象、unit 分配、Material 语义分离。Material 应说明纹理是 baseColor、normal、lightMap 还是 mask，而不是只叫 texture2。颜色数据通常需 sRGB 解码；normal/roughness/mask 是线性数据，不能解码。

验收：先让 shader 只输出第一图；用 Spector/状态日志确认 active unit 0、TEXTURE_2D binding、sampler 值三者一致，再进入下一例。

### 基线状态表

draw 前 current program 必须是纹理 program，VAO 提供 position/UV，unit0 的 TEXTURE_2D binding 指向已 complete 对象，uSampler 值为 0。四者任何一个错都可能得到黑色，但诊断位置不同：attribute 看 UV debug，texture 看占位，unit/sampler 看绑定日志。

加载与渲染解耦：Texture.ready 只改变资源状态，Renderer 在 material bind 时选择真实/占位对象。不要让 Image.onload 自己调用 draw，因为多个资产到达会产生不可控额外帧。

## 7.6 多纹理完成版

[源码：ch07_06_multi-texture-final.html](https://github.com/PacktPublishing/Real-Time-3D-Graphics-with-WebGL-2/blob/master/ch07/ch07_06_multi-texture-final.html)

最终例创建 `texture` 与 `texture2`，分别绑定 TEXTURE0/1，令 `uSampler=0`、`uSampler2=1`。片元输出两次采样结果相乘。

乘法适合 light/detail modulation，但会变暗；加法可能过曝；`mix(base,overlay,mask)` 要定义 mask 来源；法线图不能直接与颜色相乘。组合公式是材质模型的一部分，必须写明输入语义与颜色空间。

WebGL 的 active unit 是全局状态。设置第二张后当前 active 仍为 1；下一段若默认“现在是 unit0”并 bind，会把资源放错槽。工程中的 material binder 应为每个 sampler 显式 active/bind/uniform，并缓存已绑定状态减少冗余。

异步加载还会产生一张已就绪、另一张未就绪的阶段；每张都应有语义合适的占位：baseColor 可洋红，lightMap 可白，normal map 应 `(0.5,0.5,1)`。

验收：让两 sampler 故意都指 0，确认结果变成第一图平方；交换 unit 内容但不改 sampler，确认 sampler 跟槽而不是跟对象；最后分别显示两个 texel 与组合输出。

### 每次 Draw 的绑定表

`activeTexture(TEXTURE0)→bind base→uSampler=0`，再 `TEXTURE1→bind light→uSampler2=1`，最后 bind VAO/draw。sampler uniform 值通常只在 program/material 建立时设一次，但 texture binding 需在会被其他 draw 改写后恢复。VAO 不保存任何 texture state。

若第二图是 light map，应在其 UV/色彩空间中采样并只调制线性 diffuse；若是 normal map，则需第10章 TBN。把两图无语义相乘只是教学组合，不应照搬为通用材质。

## 7.7 Cubemap 加载骨架

[源码：ch07_07_cubemap.html](https://github.com/PacktPublishing/Real-Time-3D-Graphics-with-WebGL-2/blob/master/ch07/ch07_07_cubemap.html)

本例可见路径仍采样 2D 纹理，同时出现 `loadCubemapFace` 骨架：为某个 `TEXTURE_CUBE_MAP_POSITIVE/NEGATIVE_X/Y/Z` target 异步上传图片。

Cubemap 是一个 texture object 的六个 face，不是六个独立 sampler。六面必须具有相同宽高、格式和 mip 层；只有全部定义且参数满足时才 complete。应先为六面都分配 1×1 占位，再并行加载，避免任一图片未到使整个 cubemap 不可采样。

samplerCube 接收方向 vec3：取绝对值最大的分量决定 face，其余分量形成面内坐标。因此输入无需单位化才能选 face，但反射/折射数学通常应 normalize，且方向空间必须与 cubemap 定义一致。

`UNPACK_FLIP_Y_WEBGL=true` 是之前 2D 路径遗留的全局状态，上传 cubemap 时可能导致面朝向混乱。加载器应在上传前显式设置所需 pixelStore 状态，并在必要时恢复，不依赖调用历史。

验收：六面使用写有 `+X/-X...` 和箭头的测试图；在轴向采样，先确认 face，再处理旋转/翻转问题。

### 异步完整性

六个 Image.onload 的完成顺序任意。每个回调 bind 同一 cube object、向自己的 face target 上传、unbind；在最后一面到达前若未预分配其余 face，cubemap incomplete。Promise.all 可报告 ready，但预占位允许中途也安全采样。

过滤/包裹应设在 `TEXTURE_CUBE_MAP`：边通常 CLAMP_TO_EDGE；如生成 mip，六面每层都必须完整。跨面无缝还依赖面边缘内容和方向约定，测试图通过后再换正式环境图。

## 7.8 Cubemap 完成版及方向审计

[源码：ch07_08_cubemap-final.html](https://github.com/PacktPublishing/Real-Time-3D-Graphics-with-WebGL-2/blob/master/ch07/ch07_08_cubemap-final.html)

configure 创建 cubeTexture，设置 LINEAR min/mag，异步上传六面；draw 在 TEXTURE1 绑定 cubemap 并让 `uCubeSampler=1`。片元把 2D texel 与 cube texel 相乘。

源码传给 cubemap 的方向并不是标准反射向量：`vVertexNormal=(uNormalMatrix*vec4(-aVertexPosition,1)).xyz`。它把负位置当“法线”，而且方向齐次 w 写 1，平移可能污染。对以原点为中心的立方体或许形成某种环境效果，但不等于正确环境反射。

严格反射：在统一 world 或 eye space计算 surface position P、单位法线 N、观察方向 V（表面指向眼睛），再 `R=reflect(-V,N)` 采样。normal 应来自 aVertexNormal，方向变换 w=0；非均匀缩放使用 normal matrix。

若做天空盒，通常绘制包围相机的 cube，View 去掉平移，projection 保留；常在不透明场景后画，depthFunc=LEQUAL，并让 clip z 写到最远。环境物体与天空盒虽都用 cubemap，输入方向和 pass 状态不同。

异步回调中多次 bind/unbind cubeTexture 合法，但缺 onerror 和统一 ready；六面尺寸不同时会 incomplete。纹理加载期间 draw 应使用已分配的六面占位。

验收：先只输出 cubemap；用方向测试图旋转相机与模型，判断环境应随世界固定而不是粘在模型。再显示 N、V、R 三个向量编码颜色，逐步定位空间或符号错误。

### Draw 与资源状态

每对象先 bind VAO，再在 unit0 绑定 2D texture、unit1 绑定 cubeTexture，两个 sampler 分别写 0/1，drawElements。当前 active unit 最终停在 1；下一材质必须显式选择，不能默认 0。六面加载 callback 也会 bind cubemap target，但不会改变 active unit，可能在当时的任意 unit 上污染 binding。

现代实现由 AssetManager 为六面校验同尺寸/格式、ready/error/dispose；Material bind 负责两个采样器。环境反射还应把 baseColor 与 reflection 用 Fresnel/roughness 组合，而非直接相乘；预过滤环境 cubemap 依 roughness 选择 mip。
