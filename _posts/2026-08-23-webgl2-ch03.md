## 01：Gouraud-Lambert

[源码](https://github.com/PacktPublishing/Real-Time-3D-Graphics-with-WebGL-2/blob/master/ch03/ch03_01_goraud-lambert.html)

相对第2章新增normal attribute、NormalMatrix和三组光照uniform。顶点shader计算颜色，片元shader只输出插值色，所以属于逐顶点/Gouraud。

点积`N·L=|N||L|cosθ`。只有N/L单位化时才直接等于余弦；`max(...,0)`消除背光负贡献。材质diffuse和光diffuse逐通道相乘，再乘角度项。

Normal不能一般地直接乘ModelView。非均匀缩放会改变切向量，保持法线与切面垂直的变换是`transpose(inverse(MV))`。方向齐次w应为0。

Draw每帧建立P，MV平移球到z=-1.5，复制MV求逆转置，上传三矩阵，绑定VAO/EBO并画三角形。Near=.1、far=10000比值很大，但场景简单。

实验：固定N=(0,0,1)，把light direction设±Z确定源码的方向约定；去掉normalize并把光长度设10；加入scale(2,1,.2)，比较MV法线与逆转置法线。输出`N*.5+.5`检查法线。

错误因果：法线反向→受光面颠倒；空间混用→光随相机错误漂移；共享硬边顶点→立方体看似圆润。

### 状态与验收边界

normal VBO/attribute format 属于 VAO，light/material/matrices 属于 program uniform，DEPTH_TEST 属于 context。切换 VAO 不会换灯，切换 program 不会换 depth。把三类状态分别记录，才能定位“第二对象继承第一对象材质”。

现代 shader 用 mat3 normalMatrix 与 vec3 normal，避免 vec4 w 写错；世界方向光用 View 的旋转部分变到 eye space。验收用 CPU 手算 `N=(0,0,1),L=(0,0,1)` 得 1，垂直得 0，背向 clamp 0，再与 readPixels 灰度比较。

## 02：旋转模型与动态光照

[源码](https://github.com/PacktPublishing/Real-Time-3D-Graphics-with-WebGL-2/blob/master/ch03/ch03_02_moving-light.html)

核心新增`angle`和`animate`。MV在平移后绕Y旋转，NormalMatrix随MV重算。模型旋转而direction uniform保持时，表面N改变，N·L随时间变化。

区分“旋转模型”和“移动光”：本源码的GUI可改光方向，动画主要旋转模型。二者画面可能相似，但数据变化位置不同：前者矩阵/法线变，后者light uniform变。

正确帧率无关写法是`angle += angularVelocity * dt`，而非每tick固定加。角度进入gl-matrix前从度转弧度。

GPU静态几何不必重传；每帧变化的是矩阵uniform。用计数器证明bufferData只初始化调用，uniformMatrix在draw调用。

实验：冻结angle只转光；固定光只转模型；同时按相反角速度转。解释三种相对方向为何可能相同或不同。

### 一帧的命令

Clock tick 先用 dt 更新 angle；draw 清 buffer，重建 `MV=T·R` 与 inverse-transpose N，上传 P/MV/N 和光 uniform，bind 静态 VAO/EBO，drawElements。bufferData 不应出现在该帧路径。

角度可用 modulo 2π 控制数值范围；不要用 Date.now 与 RAF timestamp 混合。暂停后恢复应截断 dt，避免模型瞬间跨过大角度。用相同 10 秒输入在 30/60/144Hz 比较最终旋转误差。

## 03：逐顶点Phong反射

[源码](https://github.com/PacktPublishing/Real-Time-3D-Graphics-with-WebGL-2/blob/master/ch03/ch03_03_goraud-phong.html)

Phong组合ambient、diffuse、specular。Ambient近似间接补光；diffuse由N·L；specular由反射R与眼向量V夹角的shininess次幂。

观察空间相机在原点，表面位置p的眼向量为normalize(-p)。`reflect(I,N)`要求I指向表面；符号必须与light direction约定一致。背光时应阻止镜面项，否则背面可能出现高光。

所有项在顶点shader计算为vVertexColor，再在三角形内部插值。优点是每顶点一次，缺点是高光若落在三角形内部却不在顶点上，会完全丢失。

`uShininess`越大，高光越窄。它不是PBR roughness，也不保证能量守恒。GUI分别改变灯和材质ambient/diffuse/specular，便于单项归零观察。

实验：只输出三项之一；把网格降细分；让高光在顶点间移动。记录逐顶点高光突然出现/消失的原因。

### 光照项与 GPU 阶段

`Ia=La·Ka` 与方向无关；`Id=Ld·Kd·max(N·L,0)`；`Is=Ls·Ks·max(R·V,0)^Ns`。三项在 VS 求和后成为 varying，光栅器插值的是最终颜色，不是重新计算公式。背光判断应在 specular 前应用。

每对象 draw 前重写 Ka/Kd/Ks/Ns，缺一项会继承旧材质。现代化可把材质放 UBO，并用 Blinn half vector `H=normalize(L+V)` 作为另一模型；但必须说明这会改变 Ns 的视觉对应，不能偷偷替换。

## 04：逐片元Phong

[源码](https://github.com/PacktPublishing/Real-Time-3D-Graphics-with-WebGL-2/blob/master/ch03/ch03_04_sphere-phong.html)

顶点shader不再输出最终颜色，只输出变换法线和眼向量；片元shader接收插值结果并逐片元计算完整光照。

插值两个单位法线不会保持单位长度，例如(1,0,0)与(0,1,0)中点为(.5,.5,0)，长度约.707，所以片元内必须重新normalize。

逐片元计算量随屏幕覆盖像素增长，而非只随顶点数。球占屏幕越大成本越高；质量也更稳定，内部高光不会因缺顶点丢失。

对照实验：左右画Gouraud与fragment Phong球，使用同低细分、同uniform；移动小而亮高光。用timer query而不是只看FPS比较成本。

调试顺序：固定材质色→法线色→N·L灰度→specular灰度→合成，避免一次面对复杂黑屏。

### Varying 与精度

VS 应输出 eye-space position或 L/V 与 normal；光栅器对三角形内部插值，FS 每片元 normalize、dot、pow。mediump 在移动设备的高 shininess 下可能产生带状/不稳定，可对关键向量/计算使用 highp 并检查 `getShaderPrecisionFormat`。

DEPTH_TEST 在 FS 之后/实现可 early-test 的阶段决定写入；被遮挡片元是否省去昂贵 pow 依赖 shader 是否允许 early optimization。通过缩小球屏幕面积与增加网格顶点分别测量，可区分片元与顶点成本。

## 05：墙面网格初版

[源码](https://github.com/PacktPublishing/Real-Time-3D-Graphics-with-WebGL-2/blob/master/ch03/ch03_05_wall.html)

规则墙面让插值和法线方向更容易观察。CPU生成/加载vertices和indices，再为每三角计算面法线并累加到共享顶点，最后单位化，得到平滑法线。

叉积方向由索引绕序决定。交换一个三角的两个索引，局部normal反向；光照出现黑斑或相消。退化三角形叉积为零，必须避免除零。

平面理论上所有法线一致；若normal debug出现变化，说明索引、生成算法或变换有问题。用这一简单几何验证光照系统，再迁移复杂模型。

墙细分越密，逐顶点光照插值越接近逐片元，但成本/数据增加；这不是替代逐片元光照的通用方法。

### 从加载到像素

资源 ready 后 Scene 为 position 建 VBO、为 indices 建 EBO，并由 CPU 结果建立 normal VBO；VAO 捕获三个 attribute 的读取格式。draw 清 color/depth，重算 P/MV/N，逐对象上传 material，bind VAO/EBO 后提交 TRIANGLES。GPU 顶点阶段对每个墙顶点求光照，光栅化器在密集网格内插值颜色，depth test 决定片元是否写入。

### 现代改写与验收

若墙是解析平面，可直接给恒定法线，避免运行时遍历索引；若需凹凸细节则保留低模法线，进入 normal mapping，而不是无限细分。为生成器写断言：索引数为 3 的倍数、每索引在范围内、所有输出法线有限且长度近 1。分别用一个三角、两个共享边三角和一个退化三角测试算法。

## 06：墙面完成版与状态交互

[源码](https://github.com/PacktPublishing/Real-Time-3D-Graphics-with-WebGL-2/blob/master/ch03/ch03_06_wall-final.html)

完成版加入键盘控制并用`program.getUniform`读回当前uniform。Uniform值属于program状态；查询时需提供正确program/location。

应用自己刚设置的值应保存在JS state，不应每次从GL读回。GetUniform适合教学验证或调试，频繁查询可能同步并让数据所有权混乱。

将旧keyCode改event.key；让输入只修改state，draw统一上传。这能支持未来多program，避免回调在错误current program上写uniform。

验收：墙面normal可视化一致；光方向变化可预测；JS state与调试query一致；关闭查询不影响渲染。

### 状态变化的精确位置

键盘事件发生在浏览器事件任务中，可能位于两个 RAF 之间；直接 `uniform*` 会立即改当前 program 的 uniform storage，但不会自动要求重绘。统一 state 后，事件只改 `lightDirectionState`/dirty，下一 tick 先 use program、上传，再 draw，时序可预测。

VAO 不保存 uniform，切换墙对象不会恢复光方向；program 切换则 location 与 uniform storage 都变。`getUniform(program.handle,location)` 可能造成同步，且读到 typed array/number 的类型随 uniform 类型不同。

现代控制使用 `keydown` 的 `event.code` 并在 dispose 移除 listener。连续按键若依赖系统 key repeat 会因平台不同而变速；更好的做法记录 pressed set，在 update 中用 dt 连续改变方向。

## 07：点光源

[源码](https://github.com/PacktPublishing/Real-Time-3D-Graphics-with-WebGL-2/blob/master/ch03/ch03_07_positional-lighting.html)

方向光对所有表面使用同一L；点光使用`lightPosition - surfacePosition`，每个顶点/片元方向不同。两位置必须同空间。

先计算未单位化差向量并保存distance，再normalize。若先normalize就丢失距离，无法做衰减。经验衰减`1/(kc+kl*d+kq*d²)`；理想反平方在近距离需防发散。

源码加载plane、cone、sphere，统一管线验证曲率差异。Light position若世界空间，而surface已观察空间，Camera移动时光会错误附着；在CPU乘View或shader统一变换。

实验：显示L为颜色；加入/关闭衰减；移动Camera不动世界灯；用可见小球标光位置并检查它与真实照明重合。

### Shader 数据流

顶点 shader 先得 `Peye=MV·Plocal`，世界灯若需进入 eye space应算 `LightEye=V·LightWorld`；再把 `LightEye-Peye` 作为 varying，片元插值后 normalize。也可直接插值 Peye/Neye，在片元重建 L，语义更清楚。不要插值已 normalize 的 L 后省略片元 normalize。

点光源代理球是另一 draw：它的 Model 把小球放到 light world position，材质走 unlit/emissive 分支。GL 状态必须在代理与受光物之间显式切换，不能让 `uLightSource=true` 泄漏。

验收再加入两个距离相同但方向不同的点，确认衰减只由 d、Lambert 只由角度决定；把 light 和全部对象同量平移，世界相对光照应不变。

## 08：多材质展厅初版

[源码](https://github.com/PacktPublishing/Real-Time-3D-Graphics-with-WebGL-2/blob/master/ch03/ch03_08_showroom.html)

汽车part各有diffuse/specular/shininess。Draw前上传当前part材质，因此一个模型产生多个draw。Geometry决定形状，Material决定反射，Transform决定实例位置；源码对象把三者组合在一起。

异步part加载期间场景逐步增长。先固定片元输出Kd验证材质映射，再显示normal，最后加入点光和镜面。若直接最终光照黑屏，无法区分资产/法线/空间/材质问题。

相邻part若共享program/material可排序减少状态切换，但透明材质优先考虑正确顺序。统计每帧uniform调用和draw数，理解CPU提交成本。

### 一帧的执行链

frame begin 设 viewport、清 color/depth、更新 Camera/P；traverse 每个 ready part，计算 MV/normal，上传 Ka/Kd/Ks/Ns 等材质，bind 该 part VAO/EBO，drawElements。一个 part 尚未 ready 时不应进入列表或应有明确 loading 状态。uniform 未在某 part 重写会继承上一 part，产生“某零件颜色随机跟着前一个”的状态泄漏。

法线、位置、灯和 eye 必须统一到 eye space。汽车尺度大时 near/far 也要依据包围盒选择；clearDepth 不是 far plane。现代 renderer 将 Mesh 与 Material 分开，共享 mesh/material 时复用 GPU 资源，并维护 opaque/transparent render queue。

验收：给每 part 分配唯一纯色核对 alias/材质映射；统计加载完成顺序变化不会改变最终对象集合；切车或卸载后旧 buffers 可 dispose。

## 09：展厅完成版与本章验收

[源码](https://github.com/PacktPublishing/Real-Time-3D-Graphics-with-WebGL-2/blob/master/ch03/ch03_09_showroom-final.html)

最终版使用公共Program/Scene减少重复。必须仍能展开底层：Scene.add创建位置/法线buffer和VAO；Program缓存接口；draw设置矩阵/材质并提交。

审计重点：attribute=-1如何处理；模型自带硬边法线是否被重算覆盖；默认材质用`||`是否覆盖合法0；异步失败是否被吞；GPU资源是否可dispose。

本章项目实现三种debug mode：normal、diffuse-only、specular-only；支持Gouraud/fragment切换；点光衰减；硬边/平滑法线对比。每个变量命名带空间后缀MS/WS/VS。

验收：能从点积推导Lambert；解释inverse-transpose；定位空间混用；说明逐顶点高光丢失；让Camera移动而世界灯保持正确。

### “最终版”仍需展开

初始化顺序是 context→Program link/use→Scene/Camera/Transforms→发起资产请求→Clock draw。严谨版本应 await 必需 parts 后再进入 ready；每帧不创建 buffer/program，只更新 per-frame/per-object uniforms 和提交 draw。异常不能只 catch/console 后继续黑屏。

GPU 侧仍是同一条顶点→图元→片元→深度流水线，公共类并未新增图形能力，只改变命令组织。把示例改成 ES Modules 时显式注入 gl，避免 Program/Scene 依赖全局；为 Mesh、Program、Texture 提供 dispose。

最终回归表至少覆盖：无 normal、退化 triangle、材质 0 值、404 part、attribute 被优化、相机 resize、高 DPI、透明 d<1。每项都应有预期错误或恢复行为。
