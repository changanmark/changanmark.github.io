## 8.1 Picker 与双 Pass

[源码：ch08_01_picking.html](https://github.com/PacktPublishing/Real-Time-3D-Graphics-with-WebGL-2/blob/master/ch08/ch08_01_picking.html) · [Picker.js](https://github.com/PacktPublishing/Real-Time-3D-Graphics-with-WebGL-2/blob/master/common/js/Picker.js)

Picker 创建与 canvas drawing buffer 同尺寸的 RGBA8 texture、DEPTH_COMPONENT16 renderbuffer 和 framebuffer，分别挂到 COLOR_ATTACHMENT0/DEPTH_ATTACHMENT。颜色附件存对象 ID，深度附件使被遮挡对象的 ID 不会覆盖前景。

创建后源码没有调用 `checkFramebufferStatus`。工程代码应在附件就绪后检查 COMPLETE，并报告尺寸/格式；resize 时 `update` 重新 texImage/renderbufferStorage，同时确保 picker pass viewport 也用新尺寸。

### 一次拾取的顺序

更新矩阵；bind picker FBO；viewport=附件尺寸；clear color/depth；关闭 blend/dither 等会改 ID 的状态；`uOffscreen=true`，所有可选对象输出无光照 ID；readPixels 1×1；bind 默认 FBO；恢复 viewport/状态；解码 ID；最后正常 pass 以材质光照绘制。

源码 draw 根据 `uOffscreen` 状态切换 flat ID 输出，并在 offscreen 分支 disable BLEND。注意禁用后必须为可见 pass 显式恢复；GL 状态不会因 framebuffer 切换自动保存/恢复。

### 坐标转换

DOM 原点在左上，readPixels 原点在左下；CSS 像素还可能与 buffer 像素不同：

```js
const r = canvas.getBoundingClientRect();
const x = Math.floor((e.clientX-r.left) * canvas.width/r.width);
const y = Math.floor((r.bottom-e.clientY) * canvas.height/r.height);
```

还要 clamp 到合法范围。offsetX/Y 在 CSS transform、边框或 DPR 下不一定可靠。

`readPixels` 会同步等待 GPU 完成相关 pass，只在点击/必要时读；静态场景可缓存 ID buffer，相机、场景或尺寸变更才重画。

## 8.2 批量对象与 ID 设计

[源码：ch08_02_picking-initial.html](https://github.com/PacktPublishing/Real-Time-3D-Graphics-with-WebGL-2/blob/master/ch08/ch08_02_picking-initial.html)

这个阶段建立 Picker/callback 骨架，并准备让大量对象拥有独立位置、尺度、diffuse 和 pickingColor。关键问题从“能读一个像素”升级为“如何稳定地把字节映射回对象”。

推荐把整数 ID 0 保留为背景，24 位编码为：`r=id&255; g=(id>>8)&255; b=(id>>16)&255`，shader 收到除 255 后的颜色，readPixels 再按字节还原。用 `Map<number,object>` O(1) 查找，避免 Picker.js 当前遍历 scene 并逐颜色 compare。

源码 compare 容许每通道 ±1，是在弥补 float→normalized byte 的舍入。但 ID pass 更应关闭 BLEND、DITHER、光照、纹理、抗锯齿影响，并使用精确 byte 编码。边缘 multisample resolve 仍可能混 ID；离屏 picking FBO 本例不是 multisampled，可避免这一问题。

Picker 类直接引用全局 `gl` 与 `scene`，constructor 却只收 canvas/callback，这是隐藏依赖。现代构造应显式注入 gl；对象查找表由 picking system 自己维护，并提供 dispose 删除 texture/renderbuffer/framebuffer。

验收：生成 1000 个连续 ID，编码后再解码必须完全相等；点击背景返回 0；两物体遮挡时只返回前景；resize/DPR=2 后仍命中同一视觉点。

### 帧与事件的协作

鼠标 down 只记录请求坐标；下一次 picking pass 用与可见帧相同的 Camera/MVP 重画 ID，随后 readPixels 并更新 selection。若在事件 handler 中直接读旧 FBO，而相机刚移动但 ID buffer 未重画，就会选到上一视角。给 ID buffer 维护 dirty 标志可解决缓存一致性。

GPU pass 中每对象只需 MVP+ID，材质分支、纹理和 blend 全部关闭；深度 clear/test/write 必须与可见几何一致。带 alpha cutout 的物体若希望点击透明洞穿，则 ID shader 也必须采 alpha 并使用相同 discard 规则。

## 8.3 职责展开与辅助类边界

[源码：ch08_03_picking-no-picker.html](https://github.com/PacktPublishing/Real-Time-3D-Graphics-with-WebGL-2/blob/master/ch08/ch08_03_picking-no-picker.html)

文件名虽叫 no-picker，源码仍引入并实例化 Picker；它真正的增量是显式生成大量对象和 pickingColor，把“可拾取场景数据”展开。阅读时应以源码事实为准，不因示例名推断实现已经完全移除辅助类。

对象 label generator 产生识别色并放进 object。每帧 offscreen pass 为所有对象上传 uPickingColor；可见 pass 同一个 shader 走另一分支。单 program 减少示例代码，但工程中独立极简 ID program 更稳：只需要 position、MVP、ID，不会被材质 shader 的 alpha discard、纹理或优化分支干扰。

Picker.find 读取像素后遍历所有 scene object，并用 compare 查命中，复杂度 O(N)。ID Map 能降为 O(1)。`return false` 在 traverse callback 中是否真正中止，还取决于 Scene.traverse 实现；不要假定 Array.forEach 风格 callback 能 break。

选择集合 `pickedList` 支持 toggle：已选再次点击会移除。`stop` 调 processHits 后清空数组；回调若想异步保存列表，应复制，不能长期持有随后被清空的同一引用。

验收：显示 picker texture 到屏幕四边形，确认每对象为纯平颜色、边界与可见模型重合；统计一次点击的 GPU pass、readback 和 CPU 搜索耗时，分别定位瓶颈。

### 状态恢复清单

离屏 pass 结束不能只 bindFramebuffer(null)：还要恢复默认 framebuffer 尺寸 viewport、visible program、blend/dither、clear color 和 `uOffscreen=false`。使用 pass descriptor 或 try/finally，可防 shader/对象异常让后续画面永久停在 ID 色。

若开启 `showPickingImage`，这是调试可见 pass：直接把 ID buffer 展示/让默认 FBO输出 ID。它应与真正 picking pass 区分，避免为了显示调试图再次改变 selection。现代工具可用全屏 quad采 picker texture，保留原场景 shader 不动。

## 8.4 选择、拖动与工程改写

[源码：ch08_04_picking-final.html](https://github.com/PacktPublishing/Real-Time-3D-Graphics-with-WebGL-2/blob/master/ch08/ch08_04_picking-final.html)

最终例补齐 `hitPropertyCallback`、add/remove/process/move 回调。选中时 diffuse 改为 pickingColor，拖动时对所有 hits 改位置。它展示完整交互闭环，但像素 dx/dy 直接近似世界位移，只在固定相机/特定平面下勉强自然。

严格拖拽先把鼠标转 NDC，反投影 near/far：

```text
p_world = inverse(P·V) · p_clip；随后除以 w
rayOrigin=near；rayDir=normalize(far-near)
```

按下时求射线与工作平面交点，保存 `objectPosition-hitPoint` offset；移动时重新求交点并加 offset。这样缩放 canvas、改变相机/FOV 后拖动仍对应同一世界平面。

颜色拾取优点是自然匹配最终可见片元、对象多时 shader 成本相对固定；缺点是额外 pass 和同步 readPixels，难直接得到世界交点。CPU 射线拾取可返回距离/点/法线：先包围球/AABB 粗筛，再三角形求交，保留最小正 t；大量三角形需 BVH。

状态安全方面：picker pass 应完整声明 framebuffer、viewport、program、blend off、dither off、depth test/write、color/depth clear；visible pass 同样完整声明，不能只恢复 `uOffscreen`。异常路径也要 finally 恢复默认 FBO。

验收：相机旋转、CSS 缩放、DPR=2、对象遮挡和拖出 canvas 五种情况下逐一测试。最后显示射线与工作平面交点，证明拖动不是把屏幕像素硬加到世界 X/Y。
